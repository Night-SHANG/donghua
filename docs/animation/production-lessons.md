# 代码手绘动画：制作经验与验收流程

更新：2026-10-28。

## 1. 先读完整指南，再继承已验证的方法

本项目的视觉基础是原始 p5.brush 手绘管线：`paint()`、`inkLine()`、纸面纹理、低幅笔触变化、成熟表情工具、镜头与时间轴。不能只读技能标题或摘要，更不能用平涂 SVG、静态插画平移替代它，却声称与原示例同类。

参考源：
- [OpenVideoHarness 技能入口](https://github.com/ZLHad/OpenVideoHarness/blob/main/skills/open-video-harness/SKILL.md)
- [手绘类型指南](https://github.com/ZLHad/OpenVideoHarness/blob/main/video-types/07-hand-drawn.md)
- [ClaudeAnimationBase 完整动画指南](https://github.com/JohnHeibel/ClaudeAnimationBase/blob/main/ANIMATION_GUIDE.md)

复用的是媒介、表演和工程方法，不是必须永远使用同一个角色或剧情。角色、道具、背景应使用协调的线条、色块、材质和明暗。

## 2. 有意夸张不等于意外走形

此前用短肢体和固定中性比例，是控制无意变形的一次实现选择，不是长期系列的物理禁令。

- **可以夸张：** 挤压拉伸、撞成纸片、悬空后才意识到失足、超大惯性、弹飞、道具变形，以及清楚设计的恢复动作。
- **仍是错误：** 无因果的尺寸漂移、锚点跳动、肢体脱落、部件无理由换边、前后材质不一致、遮挡或层级穿帮。
- **身份一致：** 主色、关键轮廓线索、眼神和习惯动作保持可辨识；不是每一帧都机械保持相同比例。
- **双套规范：** 中性模型表规定正常结构和锚点；表演关键姿势表规定夸张、受力、保持和恢复。

动作按“准备—发生—反应—结果”设计。眼神先引导注意，身体跟随，盖子、翅尖等次级部件最后收势；表情变化需要可读的过渡和停留。

## 3. 视觉与叙事验收不能由测试替代

语法、有限几何、帧数、编码和时长通过，只能证明技术条件，不证明好看、好笑或叙事清楚。

制作顺序：
1. 明确角色目标、阻碍、观众需要知道的信息和笑点结果。
2. 用真实 p5 管线出模型与少量关键帧，不用代用图片冒充最终效果。
3. 检查剪影、表情净空、接触与遮挡、背景层次、镜头方向和事件可读性。
4. 修正最重要的少数问题，再全片渲染；时间长度来自观众理解和反应，不是任意拉长。
5. 对**最终编码文件**检查按数值时间排序的联系表、关键动作条带、表情近裁、末帧及完整解码。
6. 声音与画面共同验收；未实际听审时不得声称已经听过。

《泡泡吹过头》的实际修正包括：模糊 marker 把手改为清晰 C 形笔绘；空白背景补充窗景、桌面和深度；壶盖跳变改为连续次级运动；泡泡冠增大；用户指出盆栽歪后，改成对称花盆、直立中央茎与连接茎的小叶。角色和场景都应接受真实画面检查。

## 4. 镜头、空间与喜剧节拍

推近推远不等于完成场景切换。先建立观众能记住的空间：方向、出入口、遮挡、通道与高低差；再用全景交代、近景反应、动作匹配和揭示切换推进信息。移动方向、视线和道具位置要连续，必要时重新建立空间。

笑点通常需要观众先看懂原因或预期，动作改变预期，再留反应和结果的时间。不要把每个动作都塞满，也不要只靠特效、抖动或更快播放制造“热闹”。

## 5. 已验证的工程路径与真实边界

详见[交付记录](../../film/teapot/DELIVERY.md)。修正版 12 个渲染分段均成功，336 帧来自同一源码提交，11 个分段重叠边界逐字节一致。

Ubuntu 22 /FFmpeg 4.4 的 CI 合成在严格逐轨时长断言失败；当时日志未打印实际轨长，不能猜测究竟哪个轨道不符，也不能称整条 CI 全绿。保存已成功分段后，在云端 FFmpeg 7.1.5 使用原音频重新封装，视频不重编码，两轨均为 14.000000 秒，原严格校验及全解码通过。复现脚本再次生成了相同 SHA256。

可复用做法：
- 先做小规模真实渲染预检；保持浏览器标准沙箱。
- 分段必须同一源码版本，帧覆盖完整，检查重叠边界。
- 原始帧、大型中间包与最终 MP4 分开，避免交付包无谓膨胀。
- 保留声音完整尾部；检查视频与音频各自时长，不只看容器时长。
- 合成失败先诊断并复用有效分段，不立刻重画全部帧，也不放宽检查掩盖问题。
- 验证器应在断言前输出并保存实际探测数据，便于区分渲染、封装和校验问题。
- 授权范围内保存源码、分镜、风格、反馈、修正和复现步骤；同步记录应能回读核验，不能只口头说“记住了”。
